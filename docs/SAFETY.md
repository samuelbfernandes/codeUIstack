# Is it safe to install? What it touches, and how you can check

This page is written so you do not have to take anyone's word for it. Everything below can be checked on your computer
in a few minutes.

## 1. Look before you run

```
codeuistack install --plan
```

prints every file it would edit, every setting it would add, every git setting it would change and every `claude`
command it would run, then stops. Nothing is changed. (From a checkout: `sh install.sh --plan`, or `install.cmd --plan` on Windows.)

## 2. Exactly what the installer may touch

| Where | What | Undo |
|---|---|---|
| `~/.claude/<name>/` | A copy of this repository's `mods/`, `global/`, `skills/`, `docs/` (the files every other change points to) and a `state/` record of what was changed | `uninstall` deletes it once the last install (everywhere or any project) is removed |
| `~/.claude/CLAUDE.md` (everywhere) or `<project>/CLAUDE.local.md` (one project) | One marked block of rules. Your text outside the block is never edited; a `.pre-<name>` backup of the original is kept | Block removed; file deleted only if the installer created it and it is now empty |
| `~/.claude/settings.json` (everywhere) or `<project>/.claude/settings.local.json` | Only the entries listed in the plan, added next to yours. An entry you already have is never overwritten, except the listed on/off settings, whose previous value is remembered | Exactly the recorded entries are removed; anything you changed since is left alone |
| `~/.claude/skills/` or `<project>/.claude/skills/` | Two skill folders. A folder with the same name is moved aside (`.bak`), not deleted | Removed only if still identical to the shipped copy |
| git config (`--global`, or `--local` in the project) | `core.hooksPath`, `toolkit.*` keys, ignore patterns. An existing `core.hooksPath` is kept unless you pass `--force-hooks` | Previous values restored |
| `<project>/.git/info/exclude` | Lines so none of the above shows up in `git status` (one-project installs) | Lines removed |
| Claude Code's plugin list | `claude plugin marketplace add <local folder>` and `claude plugin install ...`, run by Claude Code itself | `claude plugin uninstall`, run for you |

"One project" installs never write into the project's git history or its tracked files.

## 3. What it never does

- **No network.** The installer is Python standard library only and imports no networking module (CI fails if one appears).
  The only downloads are the official Anthropic plugins you tick in the checklist, and Claude Code itself downloads those.
- **No third-party code.** The installer never installs anything from outside this repository except Anthropic's own
  official plugins. Popular third-party projects are only listed in `docs/SUGGESTIONS.md`.
- **No administrator rights, no `sudo`, no shell strings.** Other programs are started in one function
  (`src/cctk/proc.py`) as an argument list with a timeout.
- **No reading of your code, keys or history.** It reads only the files it edits, and the git settings it changes.
- **No telemetry** of its own.
- **No silent changes.** With `--yes` it uses the defaults you can see with `codeuistack list`; without it, it asks and
  shows the plan before applying.

## 4. Check that what you run is what is published

- The installer is about 1,300 lines of Python in `src/cctk/`, the git guards about 330 lines of shell in `global/githooks/`.
  Both are short enough to read in an afternoon.
- The wheel (`pip`, `pipx`, `uvx`) contains the same `mods/`, `global/` and `skills/` as the repository. `codeuistack verify`
  compares your installed copy to the package and lists any changed, missing or extra file.
- Each release publishes `SHA256SUMS` for its files; build your own with `scripts/release.sh` and compare.
- Install a **tagged version**, not the moving `main` branch (`@v0.1.0` in the commands in `docs/INSTALL.md`).
- `docs/AUDIT.md` is generated by `scripts/audit.py` and checked in CI. For every mod it lists: network use (none), programs it
  starts, whether it writes files, whether it can spend model tokens. A pull request that adds any of these must change
  the allowlist in the script, where a reviewer sees it.

## 5. Things that are real, and you should know

- **Mods are code that runs inside Claude Code with your permissions.** That is how every Claude Code plugin works. These
  mods are small, make no network calls, and start only the programs in `docs/AUDIT.md`. `blast-radius` and the git guards add
  questions or refusals; they never approve anything for you.
- **A global install runs shell scripts on every `git commit` and `git push`** in every repository (git guards). They are in
  `global/githooks/`. A one-project install limits them to that repository. A repository's own hooks keep running.
- **Codex sends code to OpenAI.** If you tick the second-model review (or choose Codex in `suggest-model`), the changed code or
  your prompt is sent to Codex. That is why those items start unticked when Codex is not installed, and why `review-cost`
  shows the size first.
- **`gh`.** `branch-janitor` runs a read-only `gh pr list` (only if you have `gh`) to see whether a pull request was merged.
- **The guards are guardrails, not a security boundary.** `hardened-settings` stops Claude's file tools from reading
  credential files; it does not stop a shell command. Use the sandbox option for that, and read its trade-offs first.

## 6. What has not been verified

Written and tested on Linux without a live Claude Code session. Not verified: the mods' screens inside a real session;
the real Codex call; anything on native Windows (including `install.ps1` and `install.cmd`); the GitHub Actions workflow;
Python 3.9 at run time (checked statically only). Report what you find.
